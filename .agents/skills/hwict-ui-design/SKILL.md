# HuaWei-ICT 视觉与 UX 设计规范

> 规则改编自 ui-ux-pro-max（MIT）公开规则，为自写精简版（无搜索数据库，
> 静态规则清单）。比赛 Demo 的目标是"专业、统一、第一印象好"。

## 1. 设计系统先行（最重要的工作流）

1. **先定档位再写页面**：开工前确定 风格（如现代简约/科技感/亲和）+
   主色与语义色 + 字体搭配（标题/正文各一，最多两族）+ 圆角/密度/动效
   强度，写入 `docs/competition/design-system.md`，作为全项目视觉唯一
   事实源。
2. 之后每个页面照系统做，**不允许页面各自发挥**——"每页都好看但各好看
   各的"等于难看。
3. 需要调整时改系统文件并全局生效，不在单页打补丁。
4. 动效组件（ReactBits/anime.js）叠加在系统之上，见 `hwict-react` 第 5 节。

## 2. 十级优先规则表

| 级 | 类别 | 关键检查 | 典型反模式 |
|---|---|---|---|
| 1 | 可访问性 | 对比度≥4.5:1；图片有 alt；可键盘操作；焦点可见 | 去掉焦点环；纯图标按钮无标签 |
| 2 | 触摸与交互 | 热区≥44×44px；间距≥8px；操作有即时反馈 | 只依赖 hover；点击无任何反馈 |
| 3 | 性能 | 图片 WebP/AVIF；懒加载；预留尺寸防布局抖动 | 页面加载中跳动、闪烁 |
| 4 | 风格一致性 | 全站一种风格语言；图标同一族 SVG | 混搭拟物+扁平；拿 emoji 当图标 |
| 5 | 布局响应式 | 移动优先；无横向滚动；触底安全区 | 固定 px 宽容器；禁用缩放 |
| 6 | 排版配色 | 正文≥16px、行高≥1.5；只用语义色 token | 正文<12px；灰底灰字；组件写死 hex |
| 7 | 动画 | 时长匹配语境（微交互 120–200ms，转场 200–350ms）；动效传达含义 | 所有过渡同一时长；动画 width/height |
| 8 | 表单与反馈 | 标签可见；错误贴近字段；渐进披露 | 拿 placeholder 当标签；错误只在顶部 |
| 9 | 导航 | 返回可预期；导航项≤7；当前位置可见 | 返回行为失效；导航过载 |
| 10 | 图表 | 有图例与 tooltip；不靠颜色单独传义 | 只用红绿区分状态 |

## 3. 动效三档原则

- **档一 微交互**：按钮/输入反馈，全局默认档，所有页面可用。
- **档二 引导动效**：首屏入场、结果揭示，用于落地页与核心结果页，一页
  一处，别叠加。
- **档三 演示级**：ReactBits 组件、anime.js 编排，只用于首屏/演示页；上
  档前自问"评委现场答辩时它会不会卡"。
- 所有动效遵守 `prefers-reduced-motion`；只用 transform/opacity，不动画
  布局属性。

## 4. 反模式速查（出现即改）

灰底灰字 · 正文小字号 · emoji 当图标 · 每页不同圆角/间距 · 五颜六色的
"彩虹界面" · 无空态设计（请求失败白屏）· 动画为了炫而不是为了传达 ·
移动端点不中的小按钮 · 图表无图例。

## 5. 交付前走查

每个新页面对照第 2 节 1–6 级过一遍；演示页加走查 7 级。走查结论记入
当次开发日志（`docs/logs/`），发现的问题修复后再交付。
